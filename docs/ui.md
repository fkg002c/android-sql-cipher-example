# UI

Весь интерфейс находится в одной `MainActivity` и написан на Jetpack Compose (Material 3). Строки вынесены в `res/values/strings.xml`.

## Этапы приложения

Состояние хранит `AppViewModel` (Activity-scoped, `@HiltViewModel`):

```kotlin
data class AppUiState(stage: Stage, destination: Destination, pinError: Boolean)
```

```
            ┌─────────┐  ПИН не установлен  ┌─────────────┐  разрешения  ┌───────────┐
 запуск ──► │ LOADING │ ──────────────────► │ PERMISSIONS │ ───────────► │ SETUP_PIN │
            └─────────┘                     └─────────────┘              └─────┬─────┘
                 │ ПИН установлен                                              │ setPin()
                 ▼                                                             ▼
            ┌─────────┐        верный ПИН (unlock)        ┌──────────┐
            │ LOCKED  │ ────────────────────────────────► │ UNLOCKED │
            └─────────┘ ◄──────────────────────────────── └──────────┘
                              Activity.onStop (lock)
```

- **LOADING.** `PinManager.isPinSet()` читается на `Dispatchers.IO`, потому что первое обращение к EncryptedSharedPreferences инициализирует Keystore.
- **PERMISSIONS.** Кнопка «Разрешить» вызывает `RequestMultiplePermissions`. Переход дальше происходит при любом результате, есть кнопка «Пропустить».
- **SETUP_PIN.** Два поля: ПИН и подтверждение, 4–8 цифр. При несовпадении показывается ошибка.
- **LOCKED.** Одно поле ПИНа. При неверном вводе поле очищается и показывается «Неверный ПИН-код» (без числа оставшихся попыток). После 7-й неверной попытки подряд экран переходит в `LOADING`, `DataWiper` стирает данные и разрешения, и процесс завершается (см. [security.md](security.md#ограничение-попыток)). После верного ПИНа `unlock()` вызывает `DatabaseHolder.migrateKeyIfNeeded()`: если ПИН задан старой схемой SHA-256, БД перешифровывается ключом PBKDF2 (однократно).
- **Индикатор `busy`.** PBKDF2 (600 000 итераций) и перешифрование занимают заметное время. Пока `AppUiState.busy == true`, кнопки «Сохранить» и «Войти» неактивны и показывают `CircularProgressIndicator`, а повторные нажатия игнорируются. Поля ПИНа в это время переходят в `readOnly`: ввод игнорируется, но фокус и клавиатура остаются, поэтому после неверного ПИНа можно сразу вводить снова.
- **UNLOCKED.** Главный экран с боковым меню.

`AppRoot` в `MainActivity.kt` выбирает composable через `when (state.stage)`.

## Блокировка

`MainActivity.onStop()` вызывает `appViewModel.lock()`, если `!isChangingConfigurations`:

- поворот экрана не блокирует (ViewModel переживает пересоздание Activity);
- переход на домашний экран или в другое приложение блокирует;
- после смерти процесса создаётся новый ViewModel, и приложение стартует с `LOADING` и затем `LOCKED`.

Системный диалог разрешений не вызывает `onStop` (Activity только уходит в `onPause`), поэтому онбординг не прерывается.

## Навигация

Используется `ModalNavigationDrawer` без navigation-compose: экранов всего два, и текущий хранится в `AppUiState.destination`.

- `Destination.USERS` (иконка `Person`) и `Destination.EVENTS` (иконка `List`).
- При каждой разблокировке и после установки ПИНа `destination` сбрасывается в `USERS`, как требует ТЗ.
- В шапке меню отображается название приложения и свой номер SIM (`OwnPhoneNumber.read()`): на API 33+ через `SubscriptionManager.getPhoneNumber()`, раньше через `TelephonyManager.line1Number`. Если номер недоступен, показывается «Номер SIM недоступен».

## Экран «Пользователи»

Файлы: `ui/users/UsersScreen.kt`, `UsersViewModel.kt`.

- `LazyColumn` из `ListItem` (имя и телефон), отсортированный по имени без учёта регистра.
- **Добавление.** FAB `+` открывает `UserFormDialog` с `id = 0`.
- **Редактирование.** Тап по строке открывает тот же диалог с данными записи.
- **Удаление.** Иконка корзины открывает диалог подтверждения.
- **Валидация.** Имя не пустое, в телефоне есть хотя бы одна цифра. В поле телефона можно вводить только `0–9 + - ( )` и пробел.
- Состояние открытых диалогов хранится в `rememberSaveable` и переживает поворот экрана.

## Экран «События»

Файл: `ui/events/EventsScreen.kt`.

- `LazyColumn`, новые события сверху (`ORDER BY timestamp DESC`).
- Каждая строка показывает дату и время (`DateFormat` в локали устройства), тип события и текст «имя · номер». Если номера нет, вместо него выводится «номер скрыт».
- Список обновляется сам: Room `Flow` срабатывает, когда ресивер вставляет новую запись.
