# Безопасность: ПИН и шифрование

## Установка ПИНа

Код: `PinManager.setPin()`.

1. Генерируется соль длиной 16 байт (`SecureRandom`).
2. Вычисляется `hash = SHA-256(salt ‖ UTF-8(pin))`.
3. `salt` и `hash` в Base64 записываются в EncryptedSharedPreferences (файл `secure_prefs`, ключи `pin_salt` и `pin_sha256`) с `commit = true`.

EncryptedSharedPreferences используют `MasterKey` со схемой `AES256_GCM` из Android Keystore. Имена ключей шифруются AES256-SIV, значения — AES256-GCM.

ПИН задаётся один раз. Повторный вызов `setPin()` бросает `IllegalStateException`, потому что смена ПИНа меняет ключ БД (см. «Ограничения»).

## Проверка ПИНа

Код: `PinManager.verifyPin()`.

Хэш пересчитывается с сохранённой солью и сравнивается с эталоном через `MessageDigest.isEqual` (сравнение за постоянное время). Байты ПИНа обнуляются после хэширования.

Чтение EncryptedSharedPreferences обращается к Keystore, поэтому `AppViewModel` выполняет проверку на `Dispatchers.IO`.

## Ключ SQLCipher

Код: `PinManager.databaseKey()` и `DatabaseHolder`.

Сохранённый SHA-256 (32 байта) передаётся паролем в `SupportOpenHelperFactory(byte[])`. SQLCipher сам выводит из него ключ страниц через PBKDF2-HMAC-SHA512 и собственную соль в заголовке файла БД.

## Модель угроз

Ресивер должен записывать события, пока UI заблокирован и ПИН не введён. Из-за этого ключ БД обязан быть доступен без участия пользователя. Получается следующее:

| От чего защищает | От чего не защищает |
|---|---|
| копирование файла `sandbox.db` с устройства или из бэкапа: без ключа файл не читается | злоумышленник, исполняющий код от имени приложения (root, отладка debug-сборки): он прочитает ключ из EncryptedSharedPreferences без ПИНа |
| просмотр данных в UI без знания ПИНа | извлечение ключа Keystore на устройствах без аппаратного хранилища |

Иными словами, БД фактически защищена ключом Android Keystore, а ПИН закрывает только вход в UI.

## Ограничения и рекомендации

- **Слабое хэширование.** SHA-256 от ПИНа из 4–8 цифр перебирается за доли секунды, если хэш и соль утекли. Если ТЗ можно менять, лучше использовать PBKDF2 (сотни тысяч итераций) или Argon2.
- **Нет ограничения попыток.** Неверный ПИН только показывает ошибку. Для продакшена стоит добавить счётчик попыток с задержкой.
- **Сменить ПИН нельзя.** Для этого нужно открыть БД старым ключом, выполнить `PRAGMA rekey` с новым и только потом перезаписать хэш в префах.
- **Deprecated API.** `androidx.security:security-crypto` 1.1.0 помечен deprecated. Возможная замена — собственное шифрование через Keystore (AES-GCM) поверх DataStore.
- **Бэкап отключён.** `allowBackup="false"`, кроме того `backup_rules.xml` и `data_extraction_rules.xml` исключают `database` и `sharedpref`. Ключ Keystore не переносится на другое устройство, поэтому восстановленные файлы всё равно были бы нечитаемы.
- **Сброс.** Если ПИН забыт, остаётся только «Очистить данные» приложения. БД и настройки при этом удаляются.
